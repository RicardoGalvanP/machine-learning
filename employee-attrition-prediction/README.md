
# Employee Attrition Prediction

## Version

- English: *en
- Spanish: *es

## Problem Statement

Losing an employee costs recruiting, training and lost productivity. This project builds a binary classifier that estimates which employees are most likely to leave, so HR can start a retention conversation earlier.

The key constraint is cost asymmetry: missing someone who leaves (false negative) is more expensive than a false alarm (false positive), so recall on the "leaves" class matters more than overall accuracy. Only 16% of employees leave, so a model that always predicts "No" already reaches 83.9% accuracy; that is the baseline to beat.

## Dataset

[IBM HR Analytics Employee Attrition](https://www.kaggle.com/datasets/pavansubhasht/ibm-hr-analytics-attrition-dataset) (Kaggle): 1,470 employees, 35 variables, synthetic data generated by IBM. Four non-informative columns were dropped (three constants and an ID), leaving 30 input variables.

## Tech Stack

Python, pandas, scikit-learn (Pipeline, ColumnTransformer, GridSearchCV), seaborn, matplotlib.

## Methodology

- Stratified 70/15/15 train/validation/test split; the test set is used once.
- Exploratory analysis on the training set only: distributions, skewness, correlations, VIF, attrition rate by category.
- All preprocessing inside a scikit-learn Pipeline (median/mode imputation, Yeo-Johnson, standardization, ordinal and one-hot encoding), refit in every cross-validation fold to avoid data leakage.
- Logistic regression (no penalty, L1, L2, ElasticNet) and KNN tuned with repeated stratified 5-fold cross-validation, then re-evaluated on different splits.
- Final ElasticNet model evaluated on the test set with confidence intervals.
- Recall-oriented analysis: decision-threshold tuning (F2 on out-of-fold predictions), `class_weight`, removal of sensitive attributes (age, gender, marital status), and a per-group recall audit.

## Key Results

Cross-validated accuracy (majority baseline: 83.9%):

| Model | Accuracy (mean ± std) |
|---|---|
| Logistic regression | 0.885 ± 0.018 |
| Lasso (C = 0.3) | 0.889 ± 0.017 |
| Ridge (C = 0.3) | 0.889 ± 0.020 |
| ElasticNet (C = 1, l1_ratio = 0.3) | 0.889 ± 0.020 |
| KNN (k = 5) | 0.849 ± 0.009 |

Test set (221 employees, 36 who left; baseline accuracy 0.837):

| Scenario | Accuracy | Precision | Recall | ROC-AUC | Flagged |
|---|---|---|---|---|---|
| Threshold 0.5 | 0.860 | 0.61 | 0.39 | 0.727 | 23 |
| Tuned threshold (F2) | 0.688 | 0.29 | 0.64 | 0.727 | 79 |
| Without age, gender, marital status + tuned threshold | 0.710 | 0.31 | 0.64 | 0.719 | 74 |

- The four logistic variants are indistinguishable; regularization did not help. KNN is only 1 point above the baseline.
- The test-set accuracy edge over the baseline (+2.3 points) is within sampling noise. At the default threshold the model catches 14 of 36 leavers (recall 0.39, 95% CI 0.25-0.55).
- A lower threshold catches about 2 of 3 leavers but flags a third of the workforce with about 70% false alarms. It is the same model at another operating point, so it is a trade-off tied to the real cost of an intervention.
- Removing age, gender and marital status costs 0.01 ROC-AUC or less, so there is no performance reason to use them. Recall still differs across groups (0.60 for employees aged 40+ versus 0.83 for those under 30), probably through proxy variables.
- Cross-validated ROC-AUC (0.85) is higher than on the test set (0.73); with only 36 positives in the test set, cross-validation is the more stable estimate.

## What I Learned

- Accuracy is a poor headline on imbalanced data: always compare against the naive baseline and report recall, precision and AUC with confidence intervals.
- Preprocessing must live inside the cross-validation Pipeline, including during grid search, or information leaks across folds.
- Moving a decision threshold does not make a better model; it trades false negatives for false alarms, and the right point depends on business costs.
- Removing sensitive attributes is easy to test and can cost almost nothing, but it does not remove disparities caused by proxy variables, so a per-group audit is needed.
- Linear-model coefficients are unstable under multicollinearity; observed rates by category are a safer way to explain results.
